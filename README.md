# BillGrub

Парсер законопроектов на Ruby on Rails: загружает законопроекты из API
Государственной Думы, показывает стадию рассмотрения и полный текст,
проводит текст через нейросеть GigaChat и показывает упрощённую
(«человеческую») версию.

## Стек

- Ruby 3.4 / Rails 8.1
- Hotwire: Turbo Streams + Turbo Frames (real-time) и Stimulus
- Action Cable (адаптер solid_cable в production, async в development)
- Devise (вход/регистрация), Solid Cache / Solid Queue / Solid Cable
- SQLite, Propshaft, Kamal для деплоя

## Запуск

```bash
bin/setup          # установка зависимостей, база, сиды
bin/dev            # сервер на http://localhost:3000
```

## Ключи внешних API (безопасность)

Ключи хранятся в приватном файле `config/api_keys.yml` — он добавлен в
`.gitignore` и не попадает в git. Шаблон: `config/api_keys.example.yml`.

```bash
cp config/api_keys.example.yml config/api_keys.yml
# вставьте свои ключи и перезапустите сервер
```

| Сервис | Ключ | Где получить |
| --- | --- | --- |
| API Госдумы | `duma.key` и `duma.app_token` | http://api.duma.gov.ru/key-request — личный ключ и ключ приложения |
| GigaChat | `gigachat.client_id`, `gigachat.client_secret` | https://developers.sber.ru/gigachat — проект GIGACHAT_API_PERS |

Переменные окружения имеют приоритет над файлом: `DUMA_KEY`, `DUMA_APP_TOKEN`,
`GIGACHAT_CLIENT_ID`, `GIGACHAT_CLIENT_SECRET`. Без ключей приложение
работает: импорт и нейросеть просто недоступны, всё остальное (лайки,
история, локальное упрощение-заглушка) функционирует.

Сертификаты GigaChat: Сбер использует подпись НУЦ Минцифры. Скачайте
корневые сертификаты с https://gu-st.ru в `config/certs/` и укажите путь в
`gigachat.ca_file` (см. комментарии в шаблоне).

## Импорт из API Госдумы

Документация API: http://api.duma.gov.ru/pages/dokumentatsiya. Используются
два запроса: поиск законопроектов (`/api/:token/bills.json`) и карточка
законопроекта (`/api/:token/bill/:number.json`).

Импортируется: номер, название, пояснение, дата внесения, текущая стадия
рассмотрения (название, дата, результат), номер закона, ссылка на
официальный документ и полный текст (из документа TXT/RTF; для PDF
остаётся только ссылка).

Два способа запуска:

```bash
bin/rails "bills:import_duma[20]"                        # последние 20 законопроектов
bin/rails "bills:import_duma[20,2026-01-01,2026-03-31]"  # за период внесения
```

Либо кнопка «Загрузить из Госдумы» на главной странице (для авторизованных
пользователей) — импортирует 20 свежих законопроектов.

На сайте: список фильтруется **по дате внесения** (поля «Внесён с / по» рядом
с поиском), на карточке и в списке видна стадия, на странице законопроекта —
блок «Данные из Госдумы» и полный текст.

## Упрощение текста (GigaChat)

Провайдер выбирается автоматически:

- заполнена секция `gigachat` в `config/api_keys.yml` → настоящая нейросеть
  GigaChat (`TextSimplifier` → `GigaChat::Client`: OAuth через
  `ngw.devices.sberbank.ru`, затем `chat/completions`);
- ключей нет → локальная заглушка `NeuralSimplifier` (работает без сети).

Результат сохраняется в модель `Simplification` (имя модели, объём текста,
время), поэтому остальной код не зависит от провайдера. Длинные тексты
передаются модели в обрезке до 15 000 символов, ответ — до 2048 токенов.

## Тесты

```bash
bin/rails test                     # модульные + интеграционные тесты
bin/rails test test/integration    # только интеграционные
```

Интеграционные тесты (`test/integration`):

| Файл | Что проверяет |
| --- | --- |
| `happy_path_test.rb` | Подробный happy path: гость -> поиск -> регистрация -> упрощение текста -> лайки -> история -> выход |
| `negative_path_test.rb` | Негативные кейсы: гость без прав получает страницу входа; упрощение без исходного текста -> ошибка; повторный лайк -> без дубликата; несуществующий законопроект -> 404; изоляция личных данных |
| `likes_broadcast_test.rb` | Real-time лайки: подписка страниц на потоки Action Cable, трансляция счётчика при лайке, turbo-stream ответ контроллера |
| `duma_integration_test.rb` | Импорт из Госдумы: фильтр списка по дате внесения, стадия и полный текст на карточке, кнопка синхронизации (без ключа -> подсказка, с ключом -> сводка), ошибка API -> понятное сообщение |

Сервисные тесты (`test/services`) проверяют маппинг JSON Госдумы, импорт с
фейковым HTTP-транспортом, RTF-извлечение текста, OAuth-цикл GigaChat и
выбор провайдера в `TextSimplifier` — настоящая сеть в тестах не используется.

## Real-time лайки (Action Cable + Turbo Streams + Turbo Frames)

Страница законопроекта и карточки на главной подписаны на собственный поток
каждого законопроекта (`turbo_stream_from bill, :likes`). Когда любой пользователь
ставит или снимает лайк:

1. Модель `Bookmark` (after_commit) транслирует `turbo-stream action="replace"`
   в поток `[bill, :likes]` — счётчик лайков обновляется у всех открытых страниц
   без перезагрузки.
2. Автору действия контроллер отвечает turbo-stream'ом, который заменяет счётчик
   и кнопку лайка, обёрнутую в Turbo Frame `like_button_bill_<id>`.

Проверить вживую: откройте карточку одного законопроекта в двух окнах браузера
(в одном — под другим пользователем) и поставьте лайк. Счётчик «лайк/лайка/лайков»
изменится в обоих окнах без перезагрузки. Триггер трансляции вручную:

```ruby
Bill.find(1).broadcast_likes
```
